# Architecture and security boundaries

The deterministic planner combines ordinary English with explicit operator-selected source files and validation names. It does not ask a model to choose commands or authority. Disk state stores the complete plan, its SHA-256 digest, local approval decision, attempt/repair records, command exit codes and durations, output digests/lengths, validated source hashes, checkpoint hash, and outcome. It does not store raw process output, environment variables, or authentication data.

## Execution

The coordinator acquires nonblocking state-directory and per-workspace flock locks. State is private (0700 directory, 0600 JSON), atomically replaced, and fsynced. A main-thread wall clock timer covers execution including Git overhead. Each subprocess has a separate output cap and timeout supervisor. Provider invocations are also counted at the HTTP broker: Aider's internal retries cannot exceed the approved remaining inference budget. Requests are reserved before an uncertain invocation, and an interrupted invocation is never retried automatically. At most three inference requests and two repair attempts are supported; internal retries can consume the inference budget before repairs become possible.

Approved files must be clean relative to the baseline. Unrelated unstaged/untracked edits remain untouched; preexisting staged edits, detached HEAD, worktrees, symlink Git directories, merges, rebases, unmerged indexes, ignored paths, Git filters, and concurrent staged edits are refused. No reset, clean, stash, checkout, remote update, GitHub push, or installation mutation is used.

Only copies of approved source files enter the sandbox. Missing approved files are precreated in the copy; directories are read-only and only those finite regular files have writable bind mounts. Provider source output therefore cannot create another file, rename/delete a file, or replace a file with a symlink. Maximum changed files is an exact mount-count boundary. `written_bytes` is the maximum resulting approved source size, not cumulative write syscall traffic: each approved file is capped by RLIMIT_FSIZE at floor(total/files). This conservative allocation enforces the aggregate cap but may refuse a large file even when the total would fit. Runtime temporary storage has its own size-limited tmpfs; stdout is separately bounded. Repeated overwrites consume CPU/time rather than a cumulative I/O quota.

The root is assembled from read-only `/usr`, `/lib`, `/lib64`, the exact Aider virtualenv, operator-owned bootstrap/control files, and the copied source view. It does not mount the host root or home, original fixture, original `.git`, SSH, credentials, other repositories, or host `/etc`. Only null/zero/urandom device nodes are provided. `/tmp` is a fresh bounded tmpfs; no host caches or histories are reused. The operator must use a trusted, credential-free Aider runtime; the runtime is read-only but its installed code is necessarily executable inside the interpreter.

Bubblewrap requests `--unshare-all --die-with-parent --new-session --cap-drop ALL` and clears the environment. No `--share-net`, privileged operation, sudo, or fallback exists. The bootstrap applies no_new_privs, resource limits, and a libseccomp filter before importing Aider or generated validation code. The filter blocks execve/execveat, fork/vfork, non-thread clone, clone3 (ENOSYS fallback for libc threads), namespace and mount changes, process-group/session escapes, ptrace, cross-process memory access, BPF, io_uring, and keyring access. Threads are bounded separately by RLIMIT_NPROC, address-space limits, and CPU/time. RLIMIT_NPROC is per real UID and can be affected by other owner processes; the active host probe must prove it works conservatively in the actual namespace configuration. A kernel/namespace combination where it does not work is refused.

Every real provider preflight checks namespace availability and runs an operator-owned active containment probe: shell/exec denial, process creation denial, inaccessible host paths, approved writes, forbidden unapproved writes, symlink creation refusal, byte caps, thread caps, and isolated network behavior. Aider is not launched if that probe fails. The real provider additionally requires Ollama 0.23.2 and Python 3.12/Aider 0.86.2. The probe and dedicated host runner remain required; mere presence of Bubblewrap is insufficient evidence.

## Network capability

Workers have an isolated network namespace. Only provider mode receives a single read-only filesystem Unix-socket capability. A small local loopback relay inside that namespace forwards to the socket. A host-side broker permits only GET `/api/tags`, POST `/api/show`, and POST `/api/chat`, pins the exact model, denies redirects/absolute URLs and model pull/delete/push, bounds body/response sizes and metadata request counts, meters inference before forwarding, and forces nonstreaming `num_ctx=16384`, `num_predict=4096`. It connects only to 127.0.0.1:11434. No caller-selected upstream, proxy, arbitrary URL, credential forwarding, or generic TCP forwarding is provided. Validation receives no socket capability. Closing the broker on interruption closes its active upstream connection; Ollama-side cancellation latency is server-dependent and is not a guarantee of instantaneous GPU cancellation.

## Validation, publication, and checkpoints

Generation runs noninteractively with no Git, no Aider commits, no auto-test/lint, no shell suggestions, no URL detection, no analytics/update checks, isolated config/env/history, and an explicit model-settings file. The broker independently enforces the 16384 context even if Aider/LiteLLM settings differ. Runtime libraries that require subprocess helpers, online tokenizer downloads, or more resources are intentionally refused; host acceptance may reveal such incompatibilities.

Validation executes only the approved exact Python module argv, in a read-only source view with no inference broker. Failed validation can send bounded in-memory feedback to the next Aider attempt; it cannot authorize another command. Feedback is never used as executable argv. Source hashes must remain unchanged during validation. At least one Python source change and successful execution of every selected validation are required before publication or checkpoint. The runner records what the command actually reported; a unit test suite is not proof of behavioral correctness, and generated tests can be insufficient or adversarial. Operators should include independently maintained tests among the approved files.

Publication journals the validated hashes before per-file atomic replacements. Recovery compares both old and intended hashes; an already completed replacement is skipped, and any intervening owner edit causes refusal. Checkpoints use a private index, hash-object without filters, write-tree, commit-tree, and an old-HEAD-guarded update-ref. Hooks and fsmonitor are disabled for these Git operations. Only changed approved paths enter the commit. The normal index is updated only for those entries; unrelated content is never staged. The journal handles interruption after ref update by identifying the objective-specific commit and reconciling those index entries.

`PUBLISHING` and `CHECKPOINTING` retain their journal on failure for inspection/recovery. `GENERATING` or `VALIDATING` recovered after interruption become terminal `INTERRUPTED`; the operator must create and approve a new objective to try again. Successful, failed, blocked, denied, or interrupted objectives never repeat provider calls. Completed disposable candidates are removed; in-flight candidates are removed on a handled interruption. An abrupt SIGKILL can leave private candidate bytes until restart cleans them. Never supply credentials in objectives or source.

## Trust and remaining limits

The operator, allowlist/configuration, runtime installation, kernel, Git implementation, and state directory are trusted. File checks reject symlinks, hardlinks, nonregular files, hidden/configuration paths, common credential filenames, and known secret patterns in objectives/source. Secret-pattern detection cannot recognize every possible credential representation; the intended boundary is that real secrets never enter the disposable fixture or worker. No general semantic secret detector is claimed.

Locks coordinate this tool, not a malicious same-UID host actor. Path and hash checks detect ordinary concurrent edits; an adversarial owner racing path replacement or editing Git/state files is outside V1's threat model. The tool does not provide transactional rollback of an already published multi-file change; its journal supports safe forward recovery without discarding owner data. Execution is main-thread-only on Linux. Host-only mount, socket, network, process/thread, and real model behavior is pending until the dedicated acceptance command passes. This is a development candidate, with no production readiness claim.
